# EverCare AI setup

EverCare’s Flutter app calls authenticated Supabase Edge Functions. The Groq API
key stays only in Supabase Function secrets; it must never be added to Flutter,
`--dart-define`, source control, or a client-side config file.

## What is included

- `health-bp-insight` accepts only the app-corrected systolic value, diastolic
  value, and pulse. It computes the adult BP category and urgent next step on
  the server before asking Groq to write a plain-language explanation.
- `care-book-ai` is limited to the 12 local Care Book topics. Obvious
  off-topic/prompt-injection messages are ignored before Groq is called. It
  does not use health records, profiles, journals, or the NIA PDF.
- Both functions require an authenticated Supabase user and use the
  `openai/gpt-oss-20b` Groq model by default with strict JSON output.

## Configure and deploy

1. Create a Groq API key in the Groq console.
2. Store it in the Supabase project. Do not commit a real `.env` file.

   ```powershell
   supabase secrets set GROQ_API_KEY=your_groq_key
   supabase secrets set GROQ_MODEL=openai/gpt-oss-20b
   ```

3. Deploy the functions to the same Supabase project configured in
   `lib/config/supabase_config.dart`.

   ```powershell
   supabase functions deploy health-bp-insight
   supabase functions deploy care-book-ai
   ```

4. For local development only, copy `.env.example` to `supabase/functions/.env`
   and replace its placeholder value. That path is ignored by Git. Start the
   Supabase stack, then serve either function:

   ```powershell
   supabase start
   supabase functions serve health-bp-insight
   supabase functions serve care-book-ai
   ```

## Safety and privacy choices

- The `-10 mmHg` YK-IBPA1 systolic calibration is applied in the Flutter
  decoder exactly once. The raw packet systolic and offset version are retained
  in the saved BLE record metadata; manual readings are never changed.
- The health status follows adult category thresholds but is explicitly
  educational, not a diagnosis or medical verification. The severe-reading
  response is deterministic, not generated by the model.
- Care Book chats are kept in memory on the device and are not saved to the
  database. Before production, review Groq’s health-data retention/privacy
  terms and add a shared production rate limiter if usage scales beyond the
  per-function-instance cooldown included here.
- Groq model availability and free-tier limits can change. Confirm the current
  model, quotas, and data policy before release.
