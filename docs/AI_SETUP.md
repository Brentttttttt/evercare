# EverCare AI setup

EverCare’s Flutter app calls authenticated Supabase Edge Functions. The Groq API
key stays only in Supabase Function secrets; it must never be added to Flutter,
`--dart-define`, source control, or a client-side config file.

## What is included

- `health-bp-insight` accepts only the app-corrected systolic value, diastolic
  value, and pulse. It computes the adult BP category and urgent next step on
  the server before asking Groq to select from reviewed tips.
- `health-bp-chat` accepts a typed question, a bounded eight-message in-memory
  conversation window, and only those same corrected display values. Groq
  selects a reviewed intent and can write a short answer grounded entirely in
  server-reviewed facts. The server still owns categories, medical/emergency
  redirects, professional follow-up, disclaimers, and urgent guidance.
- `care-book-ai` uses the 12 local Care Book topics when they apply and can
  offer cautious general guidance about older-adult health, daily care, and
  caregiver wellbeing. Obvious off-topic and prompt-injection messages are
  redirected locally. Greetings and unrelated requests receive friendly,
  in-scope replies instead of disappearing.
  It does not use health records, profiles, journals, or the NIA PDF.
- All AI functions require an authenticated Supabase user and use the
  `openai/gpt-oss-120b` Groq model by default with strict JSON output and
  medium reasoning effort.

## Configure and deploy

1. Create a Groq API key in the Groq console.
2. Store it in the Supabase project. Do not commit a real `.env` file.

   ```powershell
   supabase secrets set GROQ_API_KEY=your_groq_key
   supabase secrets set GROQ_MODEL=openai/gpt-oss-120b
   ```

3. Deploy the functions to the same Supabase project configured in
   `lib/config/supabase_config.dart`.

   ```powershell
   supabase functions deploy health-bp-insight
   supabase functions deploy health-bp-chat
   supabase functions deploy care-book-ai
   ```

4. For local development only, copy `.env.example` to `supabase/functions/.env`
   and replace its placeholder value. That path is ignored by Git. Start the
   Supabase stack, then serve either function:

   ```powershell
   supabase start
   supabase functions serve health-bp-insight
   supabase functions serve health-bp-chat
   supabase functions serve care-book-ai
   ```

## Safety and privacy choices

- The `-10 mmHg` YK-IBPA1 systolic calibration is applied in the Flutter
  decoder exactly once. The raw packet systolic and offset version are retained
  in the saved BLE record metadata; manual readings are never changed.
- The health status follows adult category thresholds but is explicitly
  educational, not a diagnosis or medical verification. The severe-reading
  response is deterministic, not generated by the model.
- Care Book chats are kept in memory on the device and are not saved to the
  database. The current question and up to eight recent messages are sent to
  Groq so natural follow-up questions have context. Before production, review
  Groq’s health-data retention/privacy terms and add a shared production rate
  limiter if usage scales beyond the per-function-instance cooldown included
  here.
- Blood-pressure chats are also memory-only. The AI provider receives the
  user’s typed question, up to eight recent messages, corrected
  systolic/diastolic values, and pulse. EverCare does not add the raw BLE
  packet, device information, measured timestamp, account identity, profile,
  or saved health history. Anything identifying that the user types remains
  part of the submitted chat text.
- Groq model availability and free-tier limits can change. Confirm the current
  model, quotas, and data policy before release.
